# 章節歸檔技能

你已被注入 `novel-archiving` 技能。你的職責是在每章寫完後執行持久化操作：生成摘要、更新記憶、產出狀態報告。

記憶操作通過工作區文件完成，詳見 `novel-memory` 技能。

**名詞說明**：本文件「掌院學士」指主控創作流程的使用者或協調 agent（狀態報告的接收方），非另一獨立技能。

---

## 歸檔流程

每章正文完成後，**立即**按以下步驟執行歸檔：

### 步驟 1：生成章節摘要文件

**路徑**: `novel/{書名}/summary/chapter_{XX}.md`

**內容模板**:

```markdown
# 第 {X} 章 摘要 - {章節標題}

## 主要情節進展
1. [情節要點 1]
2. [情節要點 2]
3. [情節要點 3]
4. [情節要點 4]（選填）
5. [情節要點 5]（選填）

## 角色狀態變化
| 角色 | 變化前狀態 | 變化後狀態 | 變化原因 |
|------|-----------|-----------|---------|
| [角色A] | [位置/情緒/關係] | [新狀態] | [觸發事件] |
| [角色B] | ... | ... | ... |

## 新埋伏筆
- **F{XXX}**: [伏筆描述]（預計第 {Y} 章回收）

## 回收伏筆
- **F{XXX}**: [伏筆描述]（第 {Z} 章埋設，本章回收）

## 時間線
- **故事內時間**: [具體時間/時間段]
- **時間跨度**: [本章經過的時間]

## 關鍵對話/決策
- [重要對話或決策的簡述]

## 支線進度更新
| 支線 ID | 本章推進內容 | 支線當前狀態 |
|---------|------------|----------|
| [S001]  | [本章推進摘要] | 進行中，第X/Y章 |
| [S002]  | [若本章交匯多條支線，逐一列出推進狀態] | 進行中 / 已完結 |

## 遺留問題
- [如有未解決的邏輯問題或需要後續處理的事項]
```

### 步驟 2：更新設定文件

按 `novel-memory` 技能規範，更新工作區文件：

1. **全書現況** → `設定/story-so-far.md`（**覆寫更新**，非追加）
   - 更新主線目前進度一句話描述
   - **更新核心角色即時動態面板**：同步覆寫更新主角與核心角色的健康/傷殘/生理狀態、能力/境界/數值指標、關鍵消耗品與道具存量、以及最新手頭重大未決承諾/死線
   - 更新本章有變動角色的當前狀態
   - 更新活躍支線清單與未決衝突
   - 只保留「現在」，不堆疊歷史（歷史已在 `summary/` 逐章保存）

2. **角色狀態** → `設定/characters.md`
   - 追加主要角色的位置、情緒、關係變化
   - 新增角色的基本資訊

3. **伏筆台帳** → `設定/foreshadowing.md`（唯一動態來源，`plan.md` 的「主線伏筆規劃」表不再回頭同步）
   - 新埋設的伏筆（標註 ID 和預計回收章節）
   - 已回收的伏筆（標註 ID 和原始章節）

4. **時間線** → `設定/timeline.md`
   - 故事內當前時間點
   - 本章的時間跨度

5. **關係網絡** → `設定/relations.md`（條件觸發）
   - 角色關係發生重大變化時更新

6. **支線狀態** → `plan.md` 的「支線故事規劃」表格
   - 更新本章所屬支線的「當前狀態」欄（進行中 第X/Y章）
   - 如該支線本章已完結，將狀態改為「已完結」

### 步驟 3：更新世界設定（條件觸發）

**觸發條件**（滿足任一即需更新 `設定/` 對應文件）：

- 新角色首次出現 → 更新 `characters.md`
- 新的世界設定被引入 → 更新 `world.md`
- 角色關係發生重大變化 → 更新 `relations.md`
- 角色獲得新能力/新身份 → 更新 `characters.md`
- 新的組織/勢力出現 → 更新 `world.md`

### 步驟 4：確認審核回修狀態（條件觸發）

若本章或前一版本存在 `novel-review` 產出的審核報告（`novel/{書名}/review/chapter_XX_review.md`）：

- 報告中若有 🔴 致命問題，必須確認已修正完畢才能將本章標記「完成」歸檔，否則狀態報告中須標記「需要修正」並列出未解決項
- 修正完成後，在對應審核報告末尾追加「複核」段落，將該報告狀態改為 ✅ 已複核通過
- 🟡/🟢 問題不阻擋歸檔，但應記錄於狀態報告的「問題報告」欄供後續參考

### 步驟 5：產出狀態報告

向掌院學士返回以下格式的報告：

```markdown
**狀態：** 完成 / 需要修正

**審核回修：** 無待處理審核項 / 已複核通過（見 review/chapter_XX_review.md） / 尚有 🔴 未修正

**字數：** [實際字數]（容量: [X] bytes）

**對話佔比：** 約 [X]%（規範目標: 30% ~ 45%）

**角色動態狀態快照：**
- [主角名]：[生理傷患狀況 / 剩餘關鍵資源 / 核心承諾與時限]

**關鍵情節：**
- [本章主要推進的情節 1]
- [本章主要推進的情節 2]
- [本章主要推進的情節 3]

**新增伏筆：**
- F{XXX}: [伏筆 1]
- F{XXX}: [伏筆 2]

**回收伏筆：**
- F{XXX}: [伏筆描述]（第 X 章埋設）

**文件更新：**
- 設定文件: [已更新 story-so-far.md 動態面板 / characters.md / ...]
- 摘要文件: [已生成 summary/chapter_XX.md]

**問題報告：**
- [如有邏輯漏洞或設定衝突，在此說明]
- [如無問題，寫"無"]
```

## 歸檔原則

1. **立即歸檔**：章節完成後立即執行，不拖延
2. **摘要精煉**：摘要應提煉關鍵資訊，不是複述全文
3. **現況即時**：`story-so-far.md` 必須反映歸檔當下的真實現況，覆寫而非追加
4. **狀態面板同步**：主角之傷患、消耗品、境界數值與手頭重大承諾必須同步覆寫至 `story-so-far.md`，杜絕數值漂移
5. **伏筆追蹤**：嚴格維護伏筆 ID 和狀態，防止遺漏，`plan.md` 規劃表不重複同步
6. **狀態完整**：角色狀態必須包含位置、情緒、關係的最新值
7. **不遺漏**：每一步都要完成，不能跳過設定文件更新或摘要文件生成
8. **審核閉環**：致命問題未複核通過前，不視為正式完成歸檔

---

## 常見錯誤

- **忘記更新設定文件**：寫完摘要就以為歸檔完了 -> 必須同時更新 `設定/` 下的對應文件
- **伏筆狀態不同步**：摘要中記錄了伏筆但沒在 `foreshadowing.md` 中更新 -> 以 `foreshadowing.md` 為準，不需回頭改 `plan.md`
- **story-so-far.md 被當成日誌疊加**：逐章追加內容導致越寫越長 -> 每次是覆寫關鍵欄位，不是附加新段落
- **遺漏動態面板更新**：只記情節未記主角傷病與消耗品變動 -> 下一章動筆時容易狀態失憶
- **遺漏新角色**：新角色出現但沒有寫入 `characters.md` -> 檢查是否有新實體需要創建
- **時間線斷裂**：沒有記錄本章的時間進度 -> 必須更新 `timeline.md`
- **帶著未複核的紅色問題歸檔**：審核報告有 🔴 卻直接標記「完成」-> 須先修正並在報告追加複核段落
