# 小說架構設計技能

你已被注入 `novel-worldbuilding` 技能。你的職責是設計小說的整體架構：大綱、人物、世界觀、伏筆規劃。

記憶操作由 `novel-memory` 技能提供，本技能專注於**結構模板和設計方法論**。

---

## 文件結構約定

```
novel/{書名}/
├── plan.md          # 總控大綱文件
├── 設定/             # 人物/世界觀/伏筆/時間線/現況快照（見 novel-memory 技能）
├── 正文/             # 章節正文
│   ├── 第1章_標題.md
│   ├── 第2章_標題.md
│   └── ...
├── summary/         # 章節摘要
│   ├── chapter_01.md
│   ├── chapter_02.md
│   └── ...
├── review/          # 審核報告（見 novel-review 技能）
└── research/        # 調研筆記（見 novel-research 技能）
```

所有路徑基於工作區根目錄。

## 架構設計工作流

### 步驟 1：需求分析
- 分析用戶提供的主題/題材/要求
- 確定故事類型、規模、風格

### 步驟 2：世界觀構建
- 設計基礎世界規則
- 定義力量體系（如有）
- 規劃社會結構和陣營
- 將核心設定寫入 `設定/world.md`

### 步驟 3：角色設計
- 設計主要角色（主角、核心配角、反派）
- 建立角色間的關係網絡
- 規劃每個角色的成長弧線
- 將人物檔案寫入 `設定/characters.md`，關係網絡寫入 `設定/relations.md`

### 步驟 4：情節架構
- 設計核心衝突和主線
- 規劃卷章結構
- 標註高潮節點
- 安排伏筆埋設與回收（`plan.md` 的伏筆規劃表僅為初始設計稿；一旦開始寫作，動態追蹤一律轉移至 `設定/foreshadowing.md`，不再回頭同步此表）

### 步驟 5：輸出與記憶庫解構初始化
- 生成 `plan.md` 總控大綱文件
- **連動 `novel-memory` 執行解構初始化**：
  - 將角色檔案與速寫解構至 `設定/characters.md`
  - 將世界觀法則與力量體系解構至 `設定/world.md`
  - 將初始伏筆解構至 `設定/foreshadowing.md`（標記為「⚪ 待埋設」）
  - 建立時間線原點 `設定/timeline.md` 與關係網絡 `設定/relations.md`
  - 初始化 `設定/story-so-far.md`（包含故事開始前的世界現況、以及核心角色的初始動態資源/能力/健康狀態面板）
- 可調用 `novel-research` 技能檢索參考素材輔助設計

### 步驟 6：長篇大綱自檢（100 章以上必做）

一次性生成的長篇大綱容易在後段耗盡素材，導致情節不自覺重複前段內容（尤其常見於卷末收尾段落）。100 章以上的大綱產出後，須完成以下自檢才算完稿：

- **去重掃描**：用文字比對或 grep 抽出每章「標題＋摘要」，檢查是否有雷同或近乎逐字重複的段落。發現重複時，保留邏輯位置正確的一則，另一則須改寫為真正推進劇情的新內容，不得原樣保留。
- **卷終標記唯一性**：每卷只能有一個「第 X 卷終」標記，且必須落在該卷標題宣告的章節範圍終點。若同一卷內出現兩處卷終字樣或卷末狀態摘要，代表卷末已被不自覺延伸/灌水，須合併或改寫。
- **伏筆表對齊逐章標註**：`主線伏筆規劃` 表格中每條伏筆的埋設/預計回收章節，須與逐章大綱內嵌的「埋設伏筆／回收伏筆」標註逐一核對一致；並確認每條伏筆在逐章大綱中都有明確的埋設與回收標註，不能只在情節裡隱含兌現卻未標記。
- **分批產出建議**：超過 100 章的大綱建議按卷分批生成、每卷產出後即完成上述自檢再繼續下一卷，不要一次性生成全書，以降低後段複寫風險。

## 設計原則

1. **因果鏈完整**：每個事件都有因有果，不憑空發生
2. **角色驅動**：情節由角色的動機和決策推動，不是作者強行安排
3. **伏筆自然**：伏筆應在當前場景中有合理存在理由，而非刻意放置
4. **節奏規劃**：張弛有度，高潮前必有鋪墊，高潮後需要緩衝
5. **設定一致**：所有規則一旦確立，在全書中必須保持一致（除非有合理的設定內解釋）
6. **自檢優先於規模**：長篇大綱的可信度優先於章節數量，寧可分批產出並依步驟 6 自檢，也不要一次性衝出全部章節數而讓後段淪為灌水重複
